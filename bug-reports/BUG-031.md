## BUG-031: Decimal value of `totalprice` property is rounded to an integer on POST/PUT/PATCH endpoints  
**Priority:** P1  
**Severity:** Critical     
**Created by:** Buha Andrii    

**Endpoint:** `PUT /booking/{id}`, `POST /booking`, `PATCH /booking/{id}`   
**Environment:** URL https://restful-booker.herokuapp.com; Tool Postman v12.22.4

### Description
There is data loss in case when user puts decimal value of `totalprice`. The booking is still created/updated.

### Precondition
This steps are only needed for PUT/PATCH endpoints. Can be skipped for `POST /booking`.
1. Authentication is required for PUT/PATCH endpoints  (see [SWAT-33928](https://github.com/Buha-Andrey/testing-of-API/blob/main/test-cases/TC-AUTH.md#id-swat-33928---title-authentication-with-valid-credentials)).
2. Create test booking with valid data (see [SWAT-33970](https://github.com/Buha-Andrey/testing-of-API/blob/main/test-cases/TC-CREATE-BOOKING.md#id-swat-33970---title-create-booking-all-fields-with-valid-data)).

### Steps to reproduce
1. Send a `PATCH /booking/{id}`
```
{
"totalprice": 2.5  
}
```
2. Check totalprice in response body

### Expected result
"totalprice": 2.5     
### Actual result 
"totalprice": 2
