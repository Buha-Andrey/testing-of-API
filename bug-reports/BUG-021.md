## BUG-021: 200 OK is returned on multiple endpoints when `depositpaid` property is set to an object, string or non-zero number
**Priority:** P1  
**Severity:** Critical    
**Created by:** Buha Andrii    

**Endpoints:** `POST /booking`, `PUT /booking/{id}`, `PATCH /booking/{id}`     
**Environment:** URL https://restful-booker.herokuapp.com; Tool Postman v12.22.4

### Description
Request with  object value, string value or not-zero number of `depositpaid` field returns status code 200 OK instead of 400 Bad Request. The booking is created and `depositpaid` is set to `true` without any error. 
This issue reproduces across multiple endpoints: `POST /booking`, `PUT /booking/{id}`, `PATCH /booking/{id}`. Actual and expected results are the same for every endpoint.  

### Steps to reproduce
1. Send a `POST /booking`
```
{
  "firstname": "Brandon",
  "lastname": "Sanderson",
  "totalprice": 1000
  "depositpaid": {
    "key": "value"
    }, 
  "bookingdates": {
    "checkin": "2025-01-01",  
    "checkout": "2026-01-01"  
  },
  "additionalneeds": "books"
}
```
2. Check status code

### Expected result
400 Bad Request     
### Actual result 
200 OK, Response body "depositpaid": true
