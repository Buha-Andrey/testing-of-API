## BUG-036: PATCH /booking/{id} returns 200 OK when `firstname`/`lastname` properties are set to a number
**Priority:** P1  
**Severity:** Major    
**Created by:** Buha Andrii    

**Endpoints:** `PATCH /booking/{id}`
**Environment:** URL https://restful-booker.herokuapp.com; Tool Postman v12.22.4

### Description
PATCH /booking/{id} Request with numeric value of the `firstname`/`lastname` returns status code 200 OK instead of 400 Bad Request.

### Precondition
1. Authentication is required for PATCH endpoint  (see [SWAT-33928](https://github.com/Buha-Andrey/testing-of-API/blob/main/test-cases/TC-AUTH.md#id-swat-33928---title-authentication-with-valid-credentials)).
2. Create test booking with valid data (see [SWAT-33970](https://github.com/Buha-Andrey/testing-of-API/blob/main/test-cases/TC-CREATE-BOOKING.md#id-swat-33970---title-create-booking-all-fields-with-valid-data)).

### Steps to reproduce
1. Send a `PATCH /booking`
```
{
  "firstname": 100,
  "lastname": 100
}
```
2. Check status code

### Expected result    
400 Bad Request       
### Actual result    
200 OK, Response Body - "firstname": 100, "lastname": 100
