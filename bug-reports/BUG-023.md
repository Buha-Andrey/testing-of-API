## BUG-023: 200 OK is returned on multiple endpoints when `checkin`/`checkout` properties are set to a number
**Priority:** P1  
**Severity:** Critical    
**Created by:** Buha Andrii    

**Endpoint:** `POST /booking`, `PUT /booking/{id}`, `PATCH /booking/{id}`   
**Environment:** URL https://restful-booker.herokuapp.com; Tool Postman v12.22.4

### Description
Request with number value of `checkin`/`checkout` fields returns status code 200 Internal Server Error instead of 400 Bad Request. The booking is created and `checkin`/`checkout` is set to random date (depends on the number) without any error. This issue reproduces across multiple endpoints: `POST /booking`, `PUT /booking/{id}`, `PATCH /booking/{id}`. Actual and expected results are the same for every endpoint.  


### Steps to reproduce
1. Send a `POST /booking`
```
{
  "firstname": "Brandon",
  "lastname": "Sanderson",
  "totalprice": 1000
  "depositpaid": true, 
  "bookingdates": {
    "checkin": 1,  
    "checkout": "2026-01-01"  
  },
  "additionalneeds": "books"
}
```
2. Check status code

### Expected result
400 Bad Request     
### Actual result 
200 OK , Response body: "checkin": "1970-01-01"
