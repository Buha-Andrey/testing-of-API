## BUG-003: POST /auth endpoint returns status code 200 OK instead of 400 Bad Request for missing Content-Type header
**Priority:** P3  
**Severity:** Minor   
**Created by:** Buha Andrii   

**Endpoint:** `POST /auth`   
**Environment:** URL https://restful-booker.herokuapp.com; Tool Postman v12.22.4

### Description
Status code 200 OK is returned when sending `POST /auth` request with invalid data types for properties and missing properties, instead of 400 Bad Request. The following cases have same results:
| Issue type | Field(s) affected | Request body |
|------------|-------------------|---------------|
| Number data type | username | `{"username" : 100,"password" : "password123"}` |
| Number data type | password | `{"username" : "admin","password" : 100}` |
| Object data type | username | `{"username" : {"key": "value"},"password" : "password123"}` |
| Object data type | password | `{"username" : "admin","password" : {"key": "value"}}` |
| Null value | username | `{"username": null, "password": "password123"}` |
| Null value | password | `{"username": "admin", "password": null}` |
| Missing key | username | `{"password": "password123"}` |
| Missing key | password | `{"username": "admin"}` |

### Steps to reproduce
1. Send request `POST /auth` with the following data:
```
Header:
Content-Type: application/json

Request body:
{
    "username" : {
        "key": "value"
    },
    "password" : "password123"
}
```
 
2. Check the status code in the response


### Expected result
400 Bad Request

### Actual result 
200 OK

**Additional info**  
Problem occurs only with the HTTP status code in the response. User doesn't get token with invalid credentials.
