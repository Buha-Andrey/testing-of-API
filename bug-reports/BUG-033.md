## BUG-032: `checkout` value is lost after `checkin` update with `PATCH /booking/{id}`
**Priority:** P1  
**Severity:** Critical     
**Created by:** Buha Andrii    

**Endpoint:** `PATCH /booking/{id}`   
**Environment:** URL https://restful-booker.herokuapp.com; Tool Postman v12.22.4

### Description
`checkout` value is set to "0NaN-aN-aN" after `checkin` using partial update `PATCH /booking/{id}`. Note that the same behaviour for `checkin` value, if we update `checkout` with `PATCH /booking/{id}`

### Precondition
1. Authentication is required for PATCH endpoint  (see [SWAT-33928](https://github.com/Buha-Andrey/testing-of-API/blob/main/test-cases/TC-AUTH.md#id-swat-33928---title-authentication-with-valid-credentials)).
2. Create test booking with valid data (see [SWAT-33970](https://github.com/Buha-Andrey/testing-of-API/blob/main/test-cases/TC-CREATE-BOOKING.md#id-swat-33970---title-create-booking-all-fields-with-valid-data)).

### Steps to reproduce
1. Send a `PATCH /booking/{id}`
```
{
        "bookingdates": {
            "checkin": "2000-06-01"
        }   
}
```
2. Check checkout in response body

### Expected result
"checkout": "2026-01-01" (same as in created test booking)    
### Actual result 
"checkout": "0NaN-aN-aN"
